# 03 · 核心代码解读

这一篇挑六段最容易“看代码看不懂意图”的地方：`edge_detect` 主链、油画 `oil_pixel5`、颜色跟踪
`color_tracks4`、帧差 `motion_*`、读页融合 `video_out_tnr`、按键 `mode_toggle`。
每个小节只讲“输入是什么、状态怎么走、为什么这么写”。

---

## 1. `edge_detect`：一条像素链，五种出口

文件：`rtl/vision/edge_detect.v`

`edge_detect` 把“灰度/色差预处理 → 两级中值 → Sobel → NMS → 双阈值 → 滞后连接 → 形态学修复”
做成一条固定深度的流水线，然后根据 `I_mode`/`I_style` 选择出口：

```verilog
wire edge_mode  = (I_mode == 2'd1);
wire bin_mode   = (I_mode == 2'd2);
wire        color_mode  = (I_mode == 2'd3) && !I_style[1];
wire [23:0] sel_rgb = edge_mode ? edge_rgb :
                      bin_mode  ? bin_rgb  :
                      color_mode ? color_sel : styled_rgb;
```

- `edge_rgb`：边缘链的输出；
- `bin_rgb`：`auto_thresh` 给出阈值后，对对齐后的灰度做 `>=` 判决；
- `color_sel`：`color_detect` 的框/标签叠加；
- `styled_rgb`：正常彩色下的油画出口；
- `I_style[1]=1` 且 `I_mode=3` 时，颜色检测关闭、`styled_rgb` 直通，运动检测在更外层绘制。

流水线用统一的行缓冲器 `line_buffer`/`cline` 保存最近若干行。油画和帧差都从这些行里“顺手”取数据，
不另开整帧缓存。

### 画廊延迟为什么是 10 行 + 29 拍

`HYST_STAGES=3` 的滞后连接需要 3 行窗口，形态学修复再要 2 行，NMS 要 1 行，两级中值各 1 行，
加上 3×3 窗口自身的 2 行历史，合计约 10 行；像素级流水是 29 拍。改 `HYST_STAGES` 会同时改行数和
`PIPE_EXTRA`，所以不要只改一个参数。

## 2. `oil_pixel5`：5×5 四桶投票

文件：`rtl/vision/edge_detect.v` 中的 `oil_pixel5`

输入是 5 行、每行 24 bit 的像素（`I_rows[119:0]`），输出一个 24 bit 像素。核心步骤：

```verilog
// 每个通道取高 4 位，亮度 = R4 + 2*G4 + B4
wire [11:0] quant = {I_rows[row*24+20+:4], I_rows[row*24+12+:4], I_rows[row*24+4+:4]};
wire [5:0] lum = {2'd0,px[11:8]} + {1'b0,px[7:4],1'b0} + {2'd0,px[3:0]};
if (lum[5:4] == k) begin nc=nc+1; nr=nr+px[11:8]; ... end
```

- 5 行来自 `cline` 的最新生行缓冲，按行号做 0~4 拍对齐；
- 4 个桶并行统计，每桶保存 `count/sum_r/sum_g/sum_b`；
- 用 20 个历史项做滑动窗口，行尾去掉 5 行前的那一列，避免每次重算 25 个像素；
- 选最多桶后，用 `value - 8n - 4n - 2n - n` 的移位减法逐位求平均，不例化除法器；
- 输出 `{mean,mean}`，即 4 bit 扩展成 8 bit。

`I_clear` 在 `!I_de` 时清空窗口，保证行首不会带入上一行残留。画面四周 `BORDER+4` 不使用油画结果，
直接透出原图，避免边界行缓冲未填满。

## 3. `color_tracks4`：每色两个候选，用代价匹配

文件：`rtl/vision/edge_detect.v` 中的 `color_tracks4`

输入是每帧从 `color_candidates_shared` 采集到的 6 个候选槽（红 2、绿 2、蓝 2），
每槽有 `x0/x1/y0/y1/area/ok`。状态机的八个状态：

```text
IDLE → DIST → ENUM → MAP → NEW → LOAD → EDGE → PUBLISH → IDLE
```

- **DIST**：候选槽 × 上一帧轨迹槽，算中心距离 + 宽高差，得到 8 个代价；
- **ENUM**：枚举“候选 0/1 → 轨迹 0/1”的配对，选匹配数最多、总代价最小的一组；
- **NEW**：没有匹配上的候选成为新轨迹；绿色只允许 1 条轨迹，用面积更大的候选替换；
- **LOAD/EDGE**：逐边做死区和平滑：`delta<=8` 不动，否则每帧最多走 24 像素；
- **PUBLISH**：提交框、面积、`ok`，丢失轨迹保持 3 帧后清除。

`admissible` 里还有尺寸门限：候选宽高必须在轨迹宽高的 0.5~2 倍之间，防止框突然“跳”到旁边的同色物体。
`gate_px` 随目标尺寸缩放（32~128 像素），大目标允许更大的帧间位移。

最终 `color_detect` 把 6 个槽交给 `osd_color_label` 画框；`color_led_status` 只取每色是否有有效框，
在 `color_mode` 下点亮对应 LED：

```verilog
O_led <= {|I_valid[5:4], |I_valid[3:2], |I_valid[1:0]};
```

## 4. `motion_*`：字级差分、行配对、中心计数

文件：`rtl/video/video_out.v` 中的 `motion_word_observer`，
`rtl/vision/osd_text.v` 中的 `motion_center_counter` / `motion_alarm_osd`

### 4.1 观测器

```verilog
wire hot = paired && (votes >= 6);          // 16 通道中至少 6 个变化
wire support = hot && (streak >= 2);        // 连续 2 个字
```

- `current_word` 与 `reference_word` 是同一地址的当前页/参考页 128 bit 字；
- 逐字节比较，绝对差 >16 记一票；16 个字节里 ≥6 票才算 hot；
- `streak` 抑制单字噪声，`row_pair` 用左右区间相距 ≤8 像素把同一行的段连起来；
- 一帧结束时输出 `packet`：`{valid, flood, motion, ymin, ymax, xmin, xmax}`；
- `flood` 表示 hot_words 超过 1/4 帧（大面积变化，通常是镜头晃动），不计为运动目标。

### 4.2 中心计数

`motion_center_counter` 用 `packet` 判“目标是否覆盖中心”：

```verilog
wire covers  = usable && (x0<=640) && (x1>=640) && (y0<=360) && (y1>=360);
wire outside = usable && ((x1<635) || (x0>645) || (y1<355) || (y0>365));
```

- 目标连续 4 帧完全离开中心，`armed` 置 1；
- 之后再次覆盖中心，计数值 +1（BCD 加法，最大 9999）；
- 只统计“进入中心”的事件，不会因为目标停在中心而每帧累加。

### 4.3 告警 OSD

`motion_alarm_osd` 把运动包跨到像素时钟域（toggle 握手 + 两级同步），并做两件事：

- 在目标框内把像素调暖：`R+255, G+128, B+128` 后右移 1 位；
- 在 (639~641, 350~370) 与 (630~650, 359~361) 画白色十字，右上角画 `COUNT:` + 4 位数字；
- 目标消失后保持 120 帧再撤掉着色，避免闪烁。

## 5. `video_out_tnr`：当前页 + 参考页

文件：`rtl/video/video_out.v` 中的 `video_out_tnr` / `tnr_word_blend`

显示侧不是“只读当前页”，而是按 48 字突发读两页：

```text
current_base   = page_base(rp)
reference_base = page_base(rp + 1)
```

- 先读当前页到 `current_buffer`，再读参考页；两边都到齐后逐字融合；
- `tnr_word_blend` 对 16 个通道分别判断 `|a-b| <= DIFF_MAX`（顶层 8），相似则取平均；
- 差异大的通道保留当前值，避免运动物体被平均成半透明；
- 参考页必须满足“有效且代数 = 当前代数 + 1”，否则 `pair_valid=0`，只输出当前页；
- 帧首会丢弃未完成的突发，`frame_pending` 等流水排空后再从新页开始，避免撕裂。

`motion_word_observer` 复用同一组 `current_word/reference_word`，因此帧差不需要第三次 DDR 读。

## 6. `mode_toggle`：按键只发请求，vsync 才生效

文件：`rtl/vision/mode_toggle.v`、`rtl/control/key_remove_shakes.v`

```verilog
if (key_pulse) req <= 1'b1;
if (vsync_rise) begin
    req <= 1'b0;
    if (req) O_mode <= (O_mode == 2'd3) ? 2'd0 : (O_mode + 2'd1);
end
```

- `key_remove_shakes` 做 4 级同步，按下沿后等 100000 个周期再确认释放，输出单周期脉冲；
- `mode_toggle` 只把脉冲记成 `req`，真正改 `O_mode` 是在 `vsync` 上升沿；
- 因此一次按键最多改一次模式，且模式切换与帧边界对齐，不会在画面中间换算法。

顶层用三个 `mode_toggle` 实例分别维护主模式、油画/原图、分块/运动；后两个的 `I_key` 在非对应模式下
被强制为 1（`I_key2 | (S_mode!=2'd0)`），这样切回主模式时子状态不会乱跳。

## 7. 读代码的顺序建议

1. 先看 `design_top_wrapper.v` 的例化顺序，建立“采集 → ISP → DDR → 显示 → 视觉”的骨架；
2. 再看 `edge_detect.v` 的端口和 578~677 行，理解五种出口；
3. 然后按需跳进 `oil_pixel5`、`color_tracks4`、`motion_*`；
4. 最后看 `video_out_tnr` 的读页状态机，理解 TNR 为什么不需要额外整帧缓存。
